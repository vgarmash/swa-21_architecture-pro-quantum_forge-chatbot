# Векторный индекс базы знаний

## Описание проекта
Создание семантического поискового индекса для базы знаний с использованием LangChain 1.x и ChromaDB.

## Используемые технологии

### Модель эмбеддингов
- **Название**: `sentence-transformers/all-MiniLM-L6-v2`
- **Репозиторий**: https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2
- **Размер эмбеддингов**: 384 измерения
- **Тип**: Модель на основе трансформеров, оптимизированная для семантического поиска

### Векторная база данных
- **Система**: ChromaDB 1.4.1
- **Индекс**: HNSW (Hierarchical Navigable Small World)
- **Метрика**: Косинусное расстояние
- **Хранение**: Локальная папка `chroma_db`

### Обработка текста
- **Фреймворк**: LangChain 1.2.4
- **Чанкер**: `chonkie.RecursiveChunker` (при наличии) с запасным sentence-aware алгоритмом
- **Refinery**: `chonkie.OverlapRefinery` (recursive/prefix), добавляет контекст предыдущего чанка
- **Размер чанка**: 400 токенов (адаптивное объединение малых чанков)
- **Перекрытие чанков**: ~15% (по токенам)

## Установка и запуск

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 2. Подготовка документов
Поместите текстовые документы в папку `knowledge_base/`.
Поддерживаемые форматы:
- .txt - текстовые файлы

### 3. Создание векторного индекса
```bash
python build_index.py
```

### Что делает build_index.py
1. Загружает `.txt` документы из `knowledge_base/` и нормализует содержимое.
2. Выделяет структурные секции (заголовки, маркированные блоки), логирует статистику по документам.
3. Пытается использовать `chonkie.RecursiveChunker` для разбиения по токенам; при недоступности библиотеки переключается на внутренний sentence-aware алгоритм.
4. Объединяет слишком короткие чанки, чтобы соблюдать минимальный порог токенов.
5. Пересоздаёт директорию `chroma_db/` и формирует коллекцию `knowledge_base` в Chroma с метаданными о модели.
6. Сохраняет индекс на диск и выводит агрегированную статистику (количество чанков, диапазон токенов, время выполнения).

## Статистика индексирования

(Пример заполнения после запуска build_index.py)

```
Модель: sentence-transformers/all-MiniLM-L6-v2
Размер эмбеддингов: 384
Документов: [количество]
Чанков: [количество]
Время индексирования: [секунды] секунд
Размер индекса: [МБ] MB
```

## Формат чанков

Каждый чанк содержит следующие метаданные:

| Поле | Описание |
|------|----------|
| `chunk_id` | Уникальный идентификатор чанка |
| `source_file` | Имя исходного файла |
| `source_path` | Полный путь к файлу |
| `chunk_index` | Порядковый номер чанка в документе |
| `total_chunks_in_doc` | Общее количество чанков в документе |
| `document_index` | Индекс документа в общей очереди |
| `title` | Автоматически сгенерированный заголовок |
| `chunk_size_chars` | Размер чанка в символах |
| `chunk_size_words` | Размер чанка в словах |
| `processing_timestamp` | Время обработки |

## Интеграция с движком RAG

Сгенерированный индекс используется сервисами в `task4/`, поэтому отдельные CLI-утилиты для поиска и диагностики не поставляются вместе с данным заданием. После выполнения `python build_index.py` новые данные становятся доступными движку RAG без дополнительных действий.

## Производительность

- **Скорость индексирования**: ~100-500 чанков/сек (зависит от оборудования)

- **Точность**: Высокая семантическая точность благодаря модели all-MiniLM-L6-v2
